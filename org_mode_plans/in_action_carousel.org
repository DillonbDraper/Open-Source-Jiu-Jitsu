* Plan To Create a Carousel for in action videos.
** Problem: The goal of in action videos is to allow users to look through short clips. Currently, they have to click out of videos by going back and then click the next one.  This is less than ideal.  We need to build an interface where a single click will go to the "next" video as informed by the video list. There are a number of possible solutions/components.  Some ideas are:
- A Mishka carousel that stages videos in a list obtained from the video list.
  - The problem with this is mostly about state passing. If they click into a video and opt into a carousel mode, the state of the list would have to be sent into the video detail view. Or, we could recalculate the list of videos based on the technique path component, or the url, both of which should have available state.
  - Another version would be to opt into a carousel mode from the video list, and have the videos pop out into a modal that is just the video carousel when they are clicked, rather than opening the video detail. I lean towards this currently as it seems simpler to manage.  If going with this we'd need to include a "InAction Carousel Mode" checkbox or toggle button above the InAction tab. We'd need to quietly query for the next page of videos if the user toggle the carousel past the last one currently loaded in the list.
  - Any other obvious implementations I'm missing?  I would be open to alternative methodologies for this.

* Collaborative Plan
** Goal
Build an inAction review mode that lets users browse short inAction clips sequentially from the current Database result set without entering the full video detail page. The first implementation should be a LiveView-managed modal player launched from the database list, with Previous/Next controls informed by the same filters, ordering, and pagination as the list.
** Final Product Decisions
- [X] Review/carousel mode defaults to off.
- [X] The review-mode toggle may render even outside the inAction tab, but the label/help text must make clear it only changes inAction video behavior.
- [X] Opening the modal remains local UI state; do not patch or change the URL.
- [X] The modal should include only the player, title, description, source link when relevant, techniques/attire/date metadata, and navigation controls; do not include full detail-page notes/share/report controls in this pass.
- [X] Next/Previous should move across loaded-page boundaries by querying adjacent pages, but disable at the true beginning/end of the available filtered result set.
- [X] New clips should load paused for now.
- [X] YouTube fallback handling is not required for inAction modal playback in the normal path because inAction records should use hosted MP4 output.
** Relevant Existing Code
- =lib/fos_bjj_web/live/videos_dashboard_live.ex=: parent LiveView for =/database= and =/videos/:id= patch states; owns query params and total count.
- =lib/fos_bjj_web/live/database_component.ex=: loads paginated videos, renders video type tabs, video cards, and pagination. This should be the primary implementation target.
- =lib/fos_bjj_web/live/video_show_component.ex=: existing detail-page player/details; useful as a reference but should not be reused wholesale for the modal because it includes detail-page concerns.
- =lib/fos_bjj_web/components/carousel.ex=: Mishka carousel component exists but is image-slide oriented; do not force it into controlling video state.
- =lib/fos_bjj_web/components/modal.ex=, =button.ex=, =card.ex=, =icon.ex=, =typography.ex=, =video.ex=: preferred UI building blocks.
** Implementation Approach
Keep the first pass inside =FosBjjWeb.DatabaseComponent=. Add a review-mode toggle and modal-specific assigns/events. When review mode is enabled and the selected video type is ="in_action"=, clicking a video card opens an inAction review modal instead of patching to the video detail route. The modal renders one hosted clip at a time and provides Previous/Next buttons that can query adjacent pages using the same Ash query semantics as the visible list.

Avoid changing routes, migrations, Ash resources, or the existing detail page behavior. Do not attempt to pass an entire list through URL params. Prefer small private helpers in =DatabaseComponent= unless extraction becomes clearly beneficial.
** Assumptions
- The filtered result set is ordered by =inserted_at: :desc=, matching the current database list.
- Page size remains 10 for both visible pagination and review navigation.
- Review navigation can maintain its own page/index state without changing the visible database page.
- Only ready, non-deleted inAction videos participate in modal review.
- Admin edit actions and technique filter buttons on cards must keep their current behavior.
- No migration or =mix ash.codegen= command is expected.
